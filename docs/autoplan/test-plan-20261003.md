真实集冻结：诊断4类每类≥2问D2–3；开发集≥10视频/30问，独立报告集目标30/100不足则披露；语言query/audio/screentext单列。标注原视频绝对区间、相关窗口、正负类别、可观察声明与支持帧/原话，由人工复核并记录分歧；版本hash固定。positive和negative不能混成一个虚增Recall数，失误/失败均保存raw outcomes；任何更改prompt/model/revision/config保留前后同集对照，fixture只检验合同。

指标协议：Recall@5为正问题相关标注窗口被top5覆盖的比例，先per-question再macro；IoU@0.5问题成功需要一对一匹配覆盖所有ground-truth事件且每个IoU≥.5，positive失败/漏项计0，negative另报正确无命中及假阳性。证据准确率按所有返回可观察claims直接被对应证据支撑的比例；空返回不贡献分母且另外报告positive任务完成/完整性，不能靠全error达标。schema总请求分母固定，raw及一次repair后分别报；任务成功率独立报告。P95已完成请求含所有服务阶段，对超时/拒绝/失败单列数与完成率，不删困难样本；hour成本基于actual window/attempt ledger。协议若与产品指标命名产生歧义须首轮前同步契约并记录版本，不能看结果再改。

实施验收顺序：每任务对应unit/integration→fixture闭环→最早真实diagnostic→D7–9阶段性能→D17–20冻结完整质量与消融→部署真实上传/query/seek/delete smoke。浏览器人工完整走键盘/读屏/触屏，mock不能证明解码和seek。所有尚未实现/未运行条目保持unchecked；未知vendor权限、U1小时预算不能用绿勾替代。
