# Token Factory cloud compiler — 2026-10-25

## Delivered and verified

The shared sampled compiler now accepts either the independently installed Mac
MLX client or a Token Factory client. The cloud transport uses only the existing
fixed-origin Provider.call and atomic owner/deployment ledger; it has no SDK
retry, JSON repair call, approval installation or GPU provisioning. JSON types,
required keys, image indices and bounded shapes are checked before accepting a
packet. Cancellation and source/owner validity are checked before dispatch.

Cloud caches bind original hash, generation, compiler and runtime/model identity;
they do not rewrite the original paid ingest or Mac MLX checkpoints. Existing
completed provider receipts are replayed, unknown/dispatched attempts are not
resent, and completed window packets reduce subsequent ingest admission.
Follow-up model context is bounded; original stored answers and source anchors
remain intact. Long cloud questions fail before paid execution.

Owned `/api/cloud-chat/prepare` and asynchronous `/api/cloud-chat` routes are wired
to the page's “云端视觉 · Token Factory” option. Execution repeats admission, so a
client cannot skip prepare to bypass the budget. The compiler remains optional
under trusted FS_CLOUD_VISION=1 and real Token Factory runtime configuration.

Actual deployment uses the existing Nebius CPU VM, one service process and the
existing mounted workspace. No dependency installation, new resource, model
training, GPU, new budget or increased cap was created. Both source and actual
installed site-packages paths were synchronized after checking the live import
path. Prior code, private databases and environment were backed up before the
service replacement. Private credentials, approvals, original videos and data
were not replaced by the release archive.
